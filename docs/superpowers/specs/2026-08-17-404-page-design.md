# Localized 404 page

## Problem

`src/pages/[...locale]/404.astro` builds to `/404/`, `/pt/404/`, `/de/404/`,
but its route is `/[...locale]/404`, which Astro does not recognise as the
error route (it requires `route === "/404"`). The Cloudflare worker therefore
serves Astro's built-in 404 template for every missing URL. The custom page is
also English-only and offers no way forward.

## Design

- New `src/pages/404.astro`, `export const prerender = false`, so the page is
  rendered on demand with the original request URL available. Locale is
  derived from the first path segment (`/pt/...`, `/de/...`, else `en`).
- `getLocale(params, url?)` in `src/lib/routes-helpers.ts` gains an optional
  URL fallback used when `params.locale` is undefined. All call sites
  (Base, BaseHead, Header, Footer, SkillsMap, Slides) pass `Astro.url`.
- Translations in `src/i18n/notFound/{types,en,pt,de}.ts`: meta title and
  description, headline, "not found at" label, link labels (home, cv, chat).
- Page renders inside `Base` (Header + Footer): "404" and headline in the
  title font, the missed path in monospace, links to Home, CV, the content
  pages from the `pages` collection (same source as Header nav), and the hero
  chat on the home page.
- Response status is 404 (Astro sets it when rendering the error route; the
  page also sets `Astro.response.status = 404` for direct visits to `/404`).
- Remove `[...locale]/404.astro` and the `/404` sitemap filter.

## Verification

`pnpm build`, then `pnpm preview` and curl `/x`, `/pt/x`, `/de/x`: status 404
and localized `<html lang>` and headline.
